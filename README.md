# 雾海对弈 · FOGBOUND

一个以海战为主题的卡牌回合制棋类游戏 MVP。支持**双人局域网房间**和**人机演习**。纯 JavaScript，零第三方运行依赖。

**[在线试玩](https://saoker-liu.github.io/IMDT-Game-Design/)** · [源代码](https://github.com/Saoker-Liu/IMDT-Game-Design)

> GitHub Pages 是静态托管，在线链接提供完整的人机演习。双人房间需要下方的 Node.js 服务；两位玩家打开同一台主机的局域网地址即可联机，无需 GitHub 或其他账号。

## 局域网双人对战

安装 **Node.js 22 或更新版本**，在一位玩家的电脑上运行：

```sh
git clone git@github.com:Saoker-Liu/IMDT-Game-Design.git
cd IMDT-Game-Design
npm start
```

未配置 GitHub SSH 的玩家也可以用 `git clone https://github.com/Saoker-Liu/IMDT-Game-Design.git`，或者下载 ZIP 后解压。无需运行 `npm install`。

1. 服务启动后会打印本机与局域网地址，例如 `http://192.168.1.10:3000`。
2. 两台设备连接同一个局域网，均在浏览器打开**同一个局域网地址**。主机也可以打开 `http://localhost:3000`。
3. 一位玩家创建房间，另一位玩家在大厅看到房间后加入；也可以输入六位房间号或使用邀请链接。
4. 双方点击「准备出航」，进入布阵阶段。

Windows 用户也可双击 `启动局域网游戏.cmd`。该脚本只启动本地 Node.js 服务。

服务默认监听 `0.0.0.0:3000`。可用环境变量 `PORT` 调整端口。主机需要允许该端口的局域网入站连接；校园网、访客 Wi-Fi 的客户端隔离可能阻止设备互访。程序不会修改系统防火墙。停止运行使用 `Ctrl+C`。

房间对连接**同一服务器**的所有玩家可见，不扫描其他主机。每个房间最多两人。房间存在于内存中，服务重启清空；房间最长保留六小时。刷新页面可凭本标签页的会话恢复身份；关闭标签页或断线超过 90 秒视作离开。对战中主动离开或断线超时，仍在房间的玩家获胜。

## 规则

| 舰型 | 每人数量 | 占据格数 |
| --- | ---: | --- |
| 护卫舰 | 4 | 1 × 1 |
| 驱逐舰 | 3 | 1 × 2 |
| 巡洋舰 | 2 | 1 × 3 |
| 战列舰 | 1 | 1 × 4 |
| 航空母舰 | 1 | 2 × 3，可旋转 |

每人 11 艘、26 格。各有一块 10 × 10 海域。舰船可相邻放置，不能重叠、越界或占据礁石。没有特殊标注的格子都是深海。

- **集结与布阵**：创建 / 加入房间，双方准备后进入最多 90 秒布阵。拖拽舰艇、`R` 旋转；舰体不可重叠、越界或占据礁石。航母完整占据六格。全部 11 艘部署后确认；超时自动补齐。
- **20 张循环牌库**：正式二十种卡各一张。开战发 4 张，每个自己的回合开始抽 2 张，包含首回合；使用完回到自己的牌库底部。手牌保留，无手牌上限。
- **行动力与回合**：每回合恢复 3 点，10 秒内连续出牌；后勤补给可增加至 3 点以上。0 点时仍可使用零费卡。主动结束、超时，或 0 点且没有零费牌时换手；出牌不重置计时。
- **舰炮与鱼雷**：副炮对战列舰无效；主炮、重炮与航弹按范围攻击所有舰型。最近的合格舰艇提供火力。行鱼雷需对应行有己方护航舰，三连发覆盖上、本、下三行；鱼雷机可选择起终点。鱼雷被舰艇、残骸、礁石阻挡，每个暗礁格独立判定 25% 受阻，深海命中保留整舰沉没效果。
- **侦察、制空与支援**：己方侦察探查半径 3 地形；信号弹、大灯泡和水上侦察机提供临时实时视野。航母可起飞战斗机、轰炸机和鱼雷机；制空权限制敌方起飞。损害管制修复一个存活舰艇部位；烟幕遮断视野并允许护航舰机动。
- **机动与地形**：三种机动卡允许沿合法航道移动最多 2 格、4 格或任意距离。不能穿过障碍，中弹、搁浅与沉没舰艇不可移动。浅滩中止航行；进入新暗礁格可能触礁沉没。暗礁外观始终同深海，己方侦察或触礁后改变悬停说明。
- **结算与再战**：消灭全部敌舰获胜；双方同意再战后，舰艇、牌库、手牌、视野、制空权和情报重置。

完整二十张卡牌表、费用、可用舰型、距离、计时及烟幕等具体定义见 **[舰队卡牌与航母规则](docs/card-system.md)**。卡面继续使用统一风格的占位图标。
手机可点击选择放置，也支持从船坞触控拖拽。音效默认关闭，可在右上角开启。支持键盘、减少动画偏好和小屏布局。

## 地形与完整海图

深海、礁石、暗礁、浅滩四类地形，以及「星罗棋布」「暗流涌动」「走向深海」三张主题地图，保留默认全深海的「无垠深海」。大厅选择海域可直接演习，创建房间也可选图；点击「地形图鉴」查看完整海图与地形效果。完整规则与早期素材站检索见 [地形与地图文档](docs/terrain-rules.md)。

v3.1 统一浅滩与深海的色调、波纹和光照，使用连续海域替换重复的逐格贴图，并以细虚线标注准确的浅滩边界。详见 [美术修订与前后对比](docs/coast-art-fix.md)。

v3.2 将礁石、暗礁也改为完整海域绘画：礁石组成自然礁群，暗礁连为水下岩脊；所有棋盘、地图预览与图鉴共用整图。格线与地形轮廓单独叠加，由规则地形数组决定准确范围。撤下旧地块图集。详见 [完整海图、美术对比与生成记录](docs/unified-map-art.md)。

v3.3.1 当时按隐蔽暗礁规则修订：暗礁始终使用深海画面，无岩纹、边界或发现标记。仅己舰触礁后，悬停才会显示对应格子的暗礁名称与效果；炮弹和鱼雷攻击不会揭示暗礁。情报按玩家分别保存，局域网对局刷新保留，再战重置。地图布局和 25% 触礁概率保留，详见 [暗礁情报沿革](docs/hidden-reefs.md)。v5.0.0 按新增卡牌规则允许己方侦察探明暗礁，临时敌方视野也可查看其地形；海面画风保持一致。

## 舰船与棋盘美术

棋盘采用细波纹海面、金属包边、黄铜刻度与罗盘；四类舰船使用独立的透明微缩模型插画。炮击分为水花、火焰烟柱和破损残骸三种状态。仅整舰击沉后显示敌舰残骸轮廓。十张 WebP 素材合计约 471 KiB，无第三方图片运行请求。手机上的开火指令紧接敌方棋盘，便于在回合时间内操作。

原始图集、完整生成提示词、参考链接与导出方法见 [美术设定](docs/art-direction.md)。网页素材位于 `public/assets/`，原始文件保留在 `art-source/`。

## 开发与验证

```sh
npm start       # 本机和局域网服务
npm run dev     # 修改服务端后自动重启
npm test        # Node 内置测试：规则与真实双客户端 HTTP 测试
npm run build  # 生成 dist 静态站点（人机试玩）
npm run check:terrain # 地图、航行、地形效果、武器与手机界面验证
npm run check:charts # 完整海图、双方朝向、所有地形轮廓与三种屏宽验证
npm run check:reefs # 暗礁隐蔽外观、炮击不揭示与触礁悬停信息、情报隔离与刷新恢复
npm run check:cards # 20 张卡、航母矩形拖拽/旋转、全套选目标方式、触屏与人机模式
```

美术浏览器验证使用隔离的无头 Edge，不读取个人浏览器资料。开发者可先 `npm install`，再运行 `npm run check:art`，检查拖拽、旋转边界、迷雾保密、炮击效果与 390px 手机布局，并输出截图到 `test-results/art/`。其他 Chromium 安装可通过 `PLAYWRIGHT_EXECUTABLE_PATH` 指定。运行游戏与规则测试无需安装此开发依赖。

```text
public/
  index.html       页面入口
  app.mjs          大厅、布阵、战斗与人机客户端
  engine.mjs       纯规则引擎，服务端与练习模式共用
  cards.mjs        二十张卡定义、费用、舰型条件、洗牌与抓牌
  cards-ui.mjs     手牌、行动力和牌库计数
  combat.mjs       火力源、范围、鱼雷、视野、制空权、修复与烟幕
  geometry.mjs     矩形舰体、距离范围、栅格连线与合法航道
  bot.mjs          只依靠卡牌与已知情报行动的演习 AI
  terrain.mjs      地形规则常量与镜像地图
  tactics-ui.mjs   地图选择、地形图鉴与航行面板
  chart-art.mjs    完整海图匹配与规则地形轮廓
  style.css        响应式深海指挥台界面
server.mjs         HTTP 静态服务、公开房间、权威对局状态、倒计时
test/              规则单元测试、HTTP 集成测试
scripts/build.mjs  静态产物构建
```

联机对局的落子、倒计时、命中与胜负全部由服务端判定。客户端以约 700ms 间隔同步状态；大厅每 2.5s 刷新。身份通过本标签页 `sessionStorage` 保存的随机 Bearer token 验证，不在 URL 中传递。未经侦察或命中的敌舰位置不会发送到客户端；侦察只返回使用者选择的单格情报，不返回完整舰体。对手的手牌和抽牌顺序也保持隐藏。人机模式完全在浏览器运行；AI 使用自己的手牌、行动力与经过迷雾过滤的视图选择目标，不读取玩家未揭示的布阵。

本地服务仅接受同源请求，限制请求体与写入频率。原型不提供账号、持久化、断点续局、跨服务器房间发现或公网生产运维。浏览器后台节流可能使人机演习倒计时延后；双人对局以服务端时间为准。

## GitHub Pages 部署

站点使用 `gh-pages` 分支的根目录发布，内容来自 `public/`，无需第三方构建依赖。主分支更新后：

```sh
npm test
npm run build
git add .
git commit -m "Update game"
git push origin main
git subtree split --prefix=public -b pages-release
git push origin pages-release:gh-pages
git branch -D pages-release
```

首次在仓库 Settings → Pages 将发布源设置为 `gh-pages` / 根目录。GitHub Pages 不运行 Node.js，不能单独承载双人房间服务。公网双人联机可将本项目完整部署到支持常驻 Node.js 的主机，启动命令同为 `npm start`，由同源地址提供页面与 API。
